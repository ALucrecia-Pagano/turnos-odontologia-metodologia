> **Precondiciones del apply**: (1) C-18 (`api-base-fastapi`) **archivado**, y (2) la autora aprobó explícitamente `design.md`. Sin las dos no se escribe código: es governance CRÍTICO. Ver grupo 0.
>
> **Regla para todas las tareas de los grupos 1 a 10: test ANTES del código.** Cada una sigue este orden:
>
> 1. Escribir los tests nombrados y correrlos **antes del código**, redirigiendo la salida a un archivo. Desde `backend/`, en Git Bash: `.venv/Scripts/python -m pytest <tests> [-m integration] > ../docs/evidencias/red-C-19/<tarea>.txt 2>&1`.
> 2. Verificar en ese archivo que fallan por la causa esperada. Un error de colección por un import inexistente cuenta como RED solo si lo que falta es lo que la tarea implementa.
> 3. **Si un test pasa de entrada, mutación obligatoria**: romper el código a propósito, ver fallar el test, restaurar, y redirigir la salida a `red-C-19/<tarea>-mutacion.txt`.
> 4. Escribir el código mínimo, refactorizar, y volver a correr los tests.
>
> **Las evidencias se generan siempre redirigiendo la salida a un archivo en UTF-8, nunca pegadas a mano.** Sin mocks, `monkeypatch` ni `dependency_overrides`. Solo datos ficticios. No se lee ni se muestra `.env`. No se edita `CHANGES.md`: sus correcciones están en `design.md`. No se commitea sin pedido de la autora.
